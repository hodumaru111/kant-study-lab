## 1. 노션 TIL DB

**스키마**: 이름(title), 날짜(date), 카테고리(select), 핵심 키워드(multi_select, 38종), 난이도(⭐1~5), 이해도(완료/복습 필요/이해 불가), Unsolved(checkbox), 소요 시간(분), 회고 만족도(1~5)

| 지표 | 값 |
|---|---|
| 총 레코드 | 21건 |
| 기간 | 2026-08-10 ~ 2026-10-06 (58일) |
| 기록된 날짜 수 | 17일 |
| **기록률** | **29% (17/58일)** |
| 마지막 기록 이후 | 4일 (10/06 → 오늘) |
| 이해도 "복습 필요" | **14건 (67%)** |
| 이해도 "완료" | 6건 |

| 회고 만족도 입력 | 20건 |

### 발견한 문제

**F-1. 복습 루프가 작동하지 않는다 (가장 심각)**
"복습 필요" 14건이 쌓여만 있고 "완료"로 바뀐 흔적이 없다. 이해도 필드가 *상태*가 아니라 *기록 당시 느낌*으로만 쓰이고 있다. 분류는 하는데 그 분류로 아무 일도 일어나지 않는다.

**F-2. Unsolved 4건 방치**
- 2026-09-08 PostgreSQL·DBeaver 실습 환경 검증
- 2026-09-17 그래프로 데이터의 이야기 보여주기
- 2026-09-22 한국어 텍스트 분류·추천 모델 개선 (난이도 ⭐⭐⭐⭐⭐)
- 2026-10-06 RDBMS vs NoSQL + 데이터 검증

`Unsolved` 뷰가 이미 노션에 있는데도 해소되지 않았다. 뷰를 만드는 것으로는 부족하고, **밀어주는 쪽(push)**이 필요하다는 증거.

**F-3. 날짜 필드를 신뢰할 수 없다**
제목의 날짜와 `날짜` 속성이 불일치한다.
- `날짜 = 2026-08-24` 인데 제목은 "26.8.25.", "26.8.26."
- `날짜 = 2026-08-25` 인데 제목은 "26.9.1."

몰아서 입력할 때 날짜를 안 고친 것으로 보인다. → **"지난주에 뭐 배웠지?" 같은 날짜 기반 질의가 틀린 답을 낸다.** 수집기는 제목에서 날짜를 파싱해 `날짜` 속성과 비교하고, 불일치 시 경고해야 한다.

**F-4. 카테고리 체계가 실제와 안 맞는다**
"기타"가 8건으로 최다. Python 기초 문법(입력, 형변환, 튜플/집합, 딕셔너리, 함수, 클래스, 조건문·반복문)이 전부 "기타"로 빠졌다. 카테고리 옵션에 해당 항목이 없기 때문. 집계·필터링이 무의미해진다.

**F-5. 프로젝트가 TIL에 섞여 있다**
`카테고리 = Project` 3건이 일일 학습 기록과 같은 테이블에 있다.
- 쇼핑몰 데이터 대시보드 (8/10)
- AX 평가 시스템 (8/20, 난이도 ⭐⭐⭐⭐)
- 개인 지출 관리 프로그램 (CSV·웹서버 연동, 난이도 ⭐⭐⭐⭐⭐)

프로젝트는 상태·마감·산출물·역할이 필요한 다른 종류의 레코드인데 TIL 스키마에는 그 필드가 없다. 포트폴리오 생성의 핵심 입력인데 가장 정보가 빈약하다.

### 발견한 문제

**F-6. 노션 TIL과 깃허브 레포 사이에 연결이 전혀 없다**
TIL의 "쇼핑몰 데이터 대시보드", "AX 평가 시스템", "개인 지출 관리"가 어느 레포인지 기록에 없다. 포트폴리오를 만들려면 *무엇을 배웠는가*(노션)와 *무엇을 만들었는가*(깃허브)를 이어야 하는데, 그 연결이 사람 머릿속에만 있다. **이 시스템이 메워야 할 핵심 공백이다.**

**F-7. 배포된 결과물이 2개 있는데 기록이 없다**
`qrcode-checkout`, `love-quiz-site` 모두 Vercel에 떠 있다. 실제 동작하는 서비스는 포트폴리오 가치가 가장 높은 자산인데 TIL에 등장하지 않는다.

**F-8. open issue 8건이 추적 대상 밖**
python_basics 6건, python_temp 2건. 할 일로 쓰이고 있다면 "지금 뭐 해야 돼?"의 입력이 되어야 한다.

## 3. 하드웨어

MacBook Air M1 (2020), **메모리 8GB 통합**, macOS Tahoe 26.5.2.

macOS가 상시 3~4GB를 쓰므로 모델에 쓸 수 있는 실질 여유는 **약 4GB**다. 브라우저·VS Code를 띄우면 더 줄어든다.

| 모델 | q4 기준 크기 | 8GB에서 |
|---|---|---|
| qwen3:4b | ~2.6GB | 동작. 체감 가능한 속도 |
| llama3.2:3b | ~2.0GB | 동작. 한국어 약함 |
| qwen3:8b | ~5.2GB | 스왑 발생, 머신 전체가 느려짐 |
| bge-m3 (임베딩) | ~1.2GB | 단독이면 여유 |

→ 생성 모델과 임베딩 모델을 **동시에 상주시키면 안 된다**. 이게 v1.0 아키텍처의 핵심 제약이다.
